# BK370 · ESP32-S3

На кожній каретці два GM25-BK370 12 В (1:9,3), MDD3A та окремі енкодери A/B. Робоча прошивка також керує серво й 12 В LED через D4184. Для двох кареток є профілі з INA226 і без нього.

| PlatformIO | Arduino IDE | Призначення |
|---|---|---|
| single | BK370_Single | Одна каретка із сайтом |
| main | BK370_Main | Каретка 1 із сайтом, ESP-NOW та INA226 |
| remote | BK370_Remote | Каретка 2 з ESP-NOW та INA226 |
| main_no_ina226 | BK370_Main_No_INA226 | Каретка 1 із сайтом та ESP-NOW, без INA226 |
| remote_no_ina226 | BK370_Remote_No_INA226 | Каретка 2 з ESP-NOW, без INA226 |
| motor_calibration | BK370_Motor_Calibration | Стендовий тест обертів і швидкості, без INA226 |
| motor_calibration_home | BK370_Motor_Calibration_Home | Той самий стендовий тест у домашньому Wi-Fi |

### Дві каретки BK370

| Підключення | Троси | Головна із сайтом | Додаткова |
|---|---|---|---|
| Wi-Fi від головної | Окремі | `main` | `remote` |
| Wi-Fi від головної | Один 20 м | `main_shared` | `remote_shared` |
| Домашній Wi-Fi | Окремі | `main_home` | `remote_home` |
| Домашній Wi-Fi | Один 20 м | `main_home_shared` | `remote_home_shared` |

У PlatformIO кожен із цих профілів має варіант із суфіксом `_no_ina226`. На платі без INA226 цей варіант прибирає телеметрію батареї та програмну відсічку за її напругою. BMS залишається захистом батареї.

**PlatformIO.** Відкрийте папку BK370 і виберіть профіль. Для Arduino IDE встановіть Arduino ESP32 3.3.12, ArduinoJson 7.4.3 і WebSockets 2.7.2. Скопіюйте library.properties і папку src у бібліотеку libraries/BK370Carriage в Arduino Sketchbook. Відкрийте скетч відповідної ролі. Плата ESP32S3 Dev Module, Flash 16 MB, QIO 80 MHz, OPI PSRAM.

**Телефон.** Для вуличного профілю під’єднайтеся до Motor-Control (початковий пароль motor8266), відкрийте [motor-control.local](http://motor-control.local/) або [192.168.4.1](http://192.168.4.1/). Для домашнього профілю введіть `HOME_WIFI_SSID` та `HOME_WIFI_PASSWORD` у `src/Settings.h` перед складанням обох прошивок. Під’єднайте телефон до тієї самої домашньої мережі й відкрийте [motor-control.local](http://motor-control.local/) або IP головної з Serial Monitor. Обидві ESP32 мають підключитися до Wi-Fi 2,4 ГГц на одному каналі. Канал ESP-NOW домашній профіль бере з Wi-Fi.

**Пара.** Внесіть station MAC обох плат із Serial Monitor (115200) у `MainMac` та `RemoteMac`. Оновіть обидві плати разом. Ланцюжок застосовує команди до обох кареток. На одному тросі спільна команда переходу до точки використовує дзеркальні координати.

## Журнал через USB і Wi-Fi

На головній сторінці відкрийте «Журнал» або додайте `/logs` до адреси ESP32. Для точки доступу використовуйте `http://192.168.4.1/logs`, для домашнього Wi-Fi — `http://motor-control.local/logs` або IP головної плати. У журналі `BK1` позначає головну каретку, `BK2` — додаткову. Час у рядку відраховується від запуску плати, яка створила подію. Після підключення сторінка читає доступну історію з оперативної пам’яті й далі оновлюється. Покази зникають із пам’яті ESP32 після перезапуску. У вебконсолі події руху й серво позначаються `START` і `END`. Завершення ходу серво визначається за розрахунковим часом. USB та UART також показують діагностику завантаження і помилки приводу. Значення INA226 та події підсвітки до текстового журналу не записуються.

У профілях без INA226 сторінка показує консоль руху та серво. Якщо датчик є хоча б на одній каретці, над консоллю з’являються графіки струму, напруги та оціненого заряду. Виберіть BK1 або BK2. Відсоток заряду доступний при прямому вимірюванні напруги батареї. Графік збирає до двох хвилин історії, поки сторінка відкрита. Після відкриття додається коротка історія, доступна в оперативній пам’яті головної ESP32.

У PlatformIO збірки BK370 вмикають нативний USB CDC. Журнал також іде через UART0. На Windows обидва типи підключення можуть з’явитися як різні COM-порти. Для кабелю в роз’ємі USB виберіть порт, що з’явився для USB Serial/JTAG. Для роз’єму UART виберіть COM USB-UART моста. Відкрийте PlatformIO Monitor на 115200 і натисніть EN. З рядка `BOOT` видно роль і режим. У Arduino IDE для нативного USB також увімкніть USB CDC On Boot та режим Hardware CDC and JTAG.

Для доступу з іншого місця підключіть головну ESP32 і ноутбук до однієї локальної мережі підсилювача. Скористайтеся віддаленим робочим столом ноутбука через приватний VPN або інший уже захищений канал і відкрийте там `/logs`. Якщо ім’я `motor-control.local` не знаходиться, використайте IP із Serial. Залишайте HTTP ESP32 всередині локальної мережі.

## INA226 на вході моторного драйвера

У двокареткових профілях з INA226 поставте по одному датчику **на кожну каретку, де потрібне вимірювання**. Датчик показує сумарний струм на вході її драйвера. Силове підключення по плюсу йде від виходу BMS через DC-запобіжник до боку шунта `IN+`, далі з боку `IN−` до плюса драйвера. Мінус драйвера і GND INA226 з’єднайте зі спільним мінусом. Для модулів із клемами `VIN/VOUT` перевірте їхню відповідність сторонам шунта за маркуванням плати. Гілки живлення ESP32 та серво беріть до шунта, якщо потрібен тільки струм драйвера.

ESP32-S3 живить логіку INA226 від **3,3 В**. SDA — GPIO8, SCL — GPIO9, GND спільний, адреса за замовчуванням `0x40`. Для профілів без датчика вибирайте суфікс `_no_ina226`. Для одного INA226 на всю головну каретку використовуйте `main_home` + `remote_home_no_ina226` або `main` + `remote_no_ina226`. Датчик стоїть перед розгалуженням на драйвер, понижувач 5 В і LED. Сайт показує напругу шини, сумарний струм і потужність головної каретки та передає ці виміри до графіків. Якщо живлення драйвера йде через стабілізатор на 12 В, поставте `InaMeasuresBatteryFeed = false`, щоб не оцінювати заряд 3S за стабілізованою напругою. Для прямого живлення з 3S збережено штатне блокування за напругою.

INA226 працює з одним перетворенням без усереднення в самому датчику. Перетворення напруги шунта й шини тривають по 588 мкс. Окрема задача ESP32 намагається зчитувати покази кожні 2 мс. На графік передаються середнє та максимум прочитаних відліків за інтервал приблизно 100 мс. Пусковий пік — максимум за перші 500 мс після появи ШІМ, якщо до цього двигуни були без ШІМ щонайменше 250 мс. Між оновленнями сторінки пік зберігає прошивка. При насиченні показується попередження про межу вимірювання. Імпульс між зчитуваннями може бути пропущений або згладжений самим перетворенням. Для перевірки найкоротших піків використовуйте осцилограф із відповідним датчиком струму.

**Один трос.** Нуль — середина 20-метрового троса. Відстань між центрами лівого і правого коліс задається в `WheelbaseMm`. Початкове значення 0 мм треба замінити виміряним. M1 вважається правим колесом (`Motor1OnRight`). Межі розраховуються за крайніми колесами, із зовнішнім запасом від 30 см і програмним зазором 1 м між внутрішніми колесами. Хід кожної каретки — до 9 м. Для 20 м троса повні 9 м ходу при цих запасах доступні з колісною базою до 200 мм. За більшої бази прошивка скорочує робочу зону.

1. Поставте каретку 1 ліворуч, каретку 2 праворуч. На сайті в ручному калібруванні вказано, скільки відміряти від кожного краю до центра зовнішнього колеса.
2. Підведіть кожну каретку до своєї мітки, відпустіть кнопку й після повної зупинки натисніть «Позначити край». До позначення доступний повільний рух у бік свого краю.
3. Натисніть «Відкалібрувати обидві до центра». Каретки прямують до внутрішніх меж зі швидкістю до 0,30 м/с. Після ввімкнення живлення мітки потрібно задавати знову.
4. Сайт показує координати обох коліс, середину каретки і відстань від зовнішньої мітки. Похибка зупинки у Serial додатна при перельоті в напрямку руху і від’ємна при недоході. Наступний відрізок починається з поточної енкодерної координати. Прослизання впливає на точність координат і фактичний зазор.

**Повернення до міток на спільному тросі.** Повернення запускається після 5 хв без команд, коли обидві каретки стоять. Єдиний відлік діє після завершення чи зупинки режиму та після ручних команд руху, серво, швидкості або підсвітки. Кожна така ручна команда починає відлік заново після зупинки кареток. Телефонні heartbeat-повідомлення відлік не скидають. Повернення запускається за чинних міток, справних приводів і зв’язку з обома каретками. СТОП під час відліку або повернення його скасовує.

Кожна каретка повертається до своєї зовнішньої мітки зі швидкістю до 0,30 м/с. Якщо після гальмування відлік вийшов за мітку, дозволено до трьох повільних корекцій у межах чинного захисту. Допуск біля мітки становить 5 мм в енкодерних координатах. Корекція зберігає попередню точку відліку. ШІМ обмежується залежно від відстані до межі, а положення визначається після докочування. Прослизання коліс накопичує похибку, яку можна прибрати повторним встановленням міток.

**Перший запуск робочої прошивки.** Перед рухом перевірте живлення, апаратне обмеження струму, ESP-NOW та відліки обох енкодерів ручним обертанням. Налаштуйте `reverseEncoder` і `reverseMotor` для кожного каналу, щоб рух вправо збільшував обидва лічильники.

**Реверс по каретках.** Головна й одиночна прошивки використовують таблицю `Motors` у `src/Settings.h`. Додаткова використовує `Carriage2Motors`. У стендовому скетчі AP або Home значення `CALIBRATE_CARRIAGE_2 = true` вибирає таблицю додаткової каретки. `reverseMotor` змінює фізичний напрямок, а `reverseEncoder` — знак відліків. У режимі вправо обидва лічильники мають зростати. Значення з перевіреної першої каретки зберігаються в `Motors`; зміни другої вносьте в `Carriage2Motors`.

**Енкодери та швидкість.** Початкові параметри — 409,2 відліку на оберт і колесо 70 мм. За можливості виміряйте й внесіть `countsPerWheelTurn` або `countsPerMeter` окремо для кожного колеса. `maxCountsPerSecond` задає опорну швидкість для регулятора і може бути замінений фактичним виміром під навантаженням. Типова опора — 1452 об/хв за номіналом. Сайт показує RPM та км/год для M1 і M2. Обидва колеса мають спільну ціль швидкості, а прошивка регулює ШІМ кожного окремо. Обраний ліміт швидкості застосовується в усіх чотирьох режимах, зокрема випадковому. Реальна швидкість залежить від навантаження, живлення та доступного ШІМ.

**Розгін і зупинка.** На відрізку до 2 м включно профіль ділить шлях на третини. На довших відрізках виділяє 1 м на розгін і 1 м на сповільнення. Остаточне гальмування починається за 3 см від цілі через `LOW/LOW` MDD3A. Якщо після гальмування каретка зупинилася завчасно, допускається контрольований повільний під’їзд до точки. Цільовий допуск — 1 см. У програмі переліт до 5 см дозволяє перейти до наступного відрізка, якщо захист меж не спрацював. Остаточна позиція обчислюється за відліками після гальмування.

**Зв’язок і помилки приводу.** Якщо сайт близько 500 мс не отримує стану, він затемнюється та показує «Немає зв’язку». Після відновлення знову видно поточний стан. Прийняті програми, проходи до цілі й калібрування виконуються на ESP32 після від’єднання телефона. Ручний рух при утриманні кнопки зупиняється, якщо команда не повторювалася 500 мс. Втрата ESP-NOW на спільному тросі або при спільному керуванні зупиняє пару.

Для кожного мотора перевірка відліків починається через 1 с безперервної команди ШІМ і повторюється кожні 500 мс. Сайт червоним показує каретку, мотор і причину. Помилки читання енкодера, запису ШІМ і відсутність відліків під час подачі команди ШІМ мають окремі повідомлення. Розбіжність положень двох коліс понад 50 см також показується червоним. У стендовому калібруванні протилежний знак відліків лишається попередженням.

**Гальмо й підсвітка.** Кнопка «СТОП» зупиняє мотори через `LOW/LOW` драйвера MDD3A. Це динамічне гальмування обертання. «СТОП» також завершує цикл серво. Червоний RGB `GPIO18` блимає під час руху або розрахункового повороту серво. Зелений `GPIO17` горить у спокої. Строб D4184 `GPIO16` працює при командних кутах серво 1–179°. У ручному калібруванні можна окремо запустити кожен вихід на 3 секунди.


## Стендовий тест обертів

Виберіть профіль PlatformIO `motor_calibration` або скетч Arduino IDE `BK370_Motor_Calibration`. Підніміть колеса над опорою, закріпіть привід і позначте початкове положення обох коліс. Перевірте живлення та захист за струмом, підключіться до `Motor-Control` і відкрийте `http://192.168.4.1/` або `http://motor-control.local/`. Кнопки доступні після ініціалізації енкодерів і виходів ШІМ.

Виберіть **M1**, **M2** або **обидва**, задайте **1–1 000 000 обертів** і ліміт ШІМ, а потім натисніть **«Вправо»** або **«Вліво»**. Кожна команда виконує один хід. Кожен вибраний мотор гальмує за власним лічильником енкодера. Сайт показує кількість відліків, поточні й максимальні RPM та середній час одного оберту за завершений хід. Підсумок також виводиться в Serial (115200).

Тест переривається після натискання «СТОП», відсутності запитів із браузера протягом 1,5 с, втрати домашнього Wi-Fi, вичерпання ліміту часу, помилки ШІМ чи енкодера, відсутності відліків протягом 1 секунди на вибраному моторі. Ліміт часу дорівнює 10 с за кожен заданий оберт і становить щонайменше 20 с. Під час довгого тесту тримайте сторінку відкритою. Якщо один мотор несправний, виберіть справний канал окремо.

Для цілі скетч бере `countsPerWheelTurn` кожного мотора або номінальні `11 × 9,3 × 4 = 409,2` відліку за оберт. Кількість фізичних обертів треба звірити за мітками. З увімкненою плавністю на старті ШІМ зростає до вибраного ліміту, з урахуванням `dutyMultiplier`. Повзунок **0–100%**: нуль блокує запуск, а 1–100% відповідають ШІМ 5–100%. Діапазон ШІМ 1–4% пропускається. Початкове значення повзунка — **20%**. Якщо колесо при вибраному ШІМ не рушає, тест завершується помилкою.

З «Плавністю» прошивка регулює швидкість кожного мотора за енкодером. На останній чверті оберту ціль становить до 60 об/хв. Прошивка дає команду гальма, коли енкодер досягає цілі. Через 200 мс без нових відліків фіксується позиція. Додатна кінцева похибка означає переліт, від’ємна — недохід.

### Калібрування через домашній Wi-Fi

1. Відкрийте [BK370_Motor_Calibration_Home.ino](<Arduino IDE/BK370_Motor_Calibration_Home/BK370_Motor_Calibration_Home.ino>) і заповніть `HOME_WIFI_SSID` та `HOME_WIFI_PASSWORD` даними домашньої мережі 2,4 ГГц. Зберігайте реальний пароль у своїй локальній копії.
2. У PlatformIO прошийте `motor_calibration_home`. В Arduino IDE завантажте цей самий скетч.
3. Підключіть телефон до тієї самої домашньої мережі й відкрийте [motor-control.local](http://motor-control.local/). Якщо ім’я не відкривається або в мережі вже є інша плата з таким ім’ям, скористайтеся IP-адресою з Serial Monitor на 115200 бод. ESP32 працює як клієнт домашньої мережі.

Під час простою Serial Monitor повторює стан Wi‑Fi приблизно кожні 10 секунд. `HOME_WIFI_SSID is empty` означає, що назву мережі потрібно вписати в Home-скетч і прошити його знову. Якщо монітор показує IP, а `motor-control.local` не відкривається, відкрийте IP у браузері з тієї самої мережі. Для профілю `motor_calibration` підключіться до точки `Motor-Control` і відкрийте [192.168.4.1](http://192.168.4.1/).

**Батарея в профілях з INA226.** 10,0 В = 0%, 12,4 В = 100%. Три послідовні виміри на рівні 10,24 В або нижче фіксують блокування. При втраті показників INA226 приводи зупиняються. Для скидання блокування потрібні щонайменше 10,50 В і явна команда з сайту. Рух після скидання запускається новою командою. Оцінка заряду орієнтовна й не гарантує відсічення раніше за BMS при розбалансованих комірках.

У калібруванні протилежний знак відліків показується попередженням на сайті та в Serial. Хід рахується за модулем зміщення кожного вибраного енкодера. Знак не зупиняє тест. Похибка зупинки також показується у міліметрах для робочого діаметра 70 мм.

У робочому інтерфейсі можна перемикатися між повзунком **«Швидкість, %»** і лімітом **«Макс. швидкість, км/год»**. Повзунок 1–100% задає стелю ШІМ, після запуску прошивки вона становить 20%. Кнопки 5, 10, 15 і 20 км/год задають цільову стелю за енкодерами. У цьому режимі діє межа ШІМ кожного мотора з `dutyMultiplier`. Плавний розгін і гальмування діють в обох режимах. Для ESP-NOW оновіть прошивки обох кареток разом. Стендове калібрування має власний повзунок і шкалу ШІМ.

У блоці «Калібрування M1 і M2» задайте стартовий і кінцевий ШІМ окремо для кожного мотора. Стартове підсилення діє до 250 мс, поки мотор набирає цільові оберти. Кінцевий ШІМ обмежує потужність на малих обертах перед гальмом. Початкові значення — 8% і 15%. Обидва параметри діють із «Плавністю» та підпорядковуються загальному ліміту ШІМ. Тут також задаються фактичні тіки за оберт. Поділіть зміну «Поточних відліків» на кількість повних фізичних обертів за міткою. Перевірені відліки можна перенести в `countsPerWheelTurn` відповідного колеса у `Settings.h`.

Галочка «Балансувати оберти M1 і M2» діє лише в режимі «Обидва» й працює незалежно від «Плавності». Після початку руху обох моторів прошивка порівнює згладжені оберти, залишає допуск 10 об/хв і плавно зменшує ШІМ швидшого мотора. Поправка обмежена половиною його команди ШІМ. Коли один мотор починає остаточно гальмувати, поправка плавно зникає. Фактичні оберти й ШІМ видно в блоці «Відліки енкодера».

На сторінці калібрування поля «Гальмувати M1 раніше, тіків» і «Гальмувати M2 раніше, тіків» задають поправки для наступного ходу. Вони приймають цілі невід’ємні значення, зокрема нуль. При відкритті сторінки початкові значення беруться з M1BrakeAdvanceTicks і M2BrakeAdvanceTicks. Значення фіксуються при запуску, тому редагування під час руху застосовується до наступної команди. Після перезавантаження сторінки повертаються початкові значення.

Галочка «Плавність» увімкнена за замовчуванням. З нею прошивка оновлює швидкість за енкодером приблизно кожні 20 мс. Рядок «Швидкість перед гальмом» показує останній замір перед командою. Без плавності заданий ШІМ подається з початку ходу до команди гальма. Якщо ввімкнене балансування, воно може зменшувати ШІМ швидшого мотора. Порівнюйте заміри при однакових напрямку, швидкості й навантаженні. Без INA226 у цьому профілі струм потрібно вимірювати зовнішнім приладом.

Після команди гальма мотор залишається в режимі гальмування до завершення ходу. На головному екрані є вибір обертів або метрів і ліміт ШІМ. Для M1 і M2 видно фактичні оберти, поточну й максимальну швидкість у км/год за енкодером та кінцеву похибку. Під час ходу в метрах також видно пройдену відстань. Тіки, точку гальма та хід у сантиметрах можна переглянути в блоці «Відліки енкодера».

Гальмівний шлях можна порівнювати між тестами за однакової швидкості, напрямку й навантаження.

Для руху за метражем виберіть «Метрах» у полі «Задати хід у», задайте відстань і виберіть напрямок. Профіль швидкості спільний для метрів і обертів. На короткому ході «Плавність» може знизити швидкість ще до виходу на ліміт, щоб залишився запас для сповільнення. Для послідовних команд у метрах прошивка накопичує неокруглену ціль окремо для кожного мотора. Наступний хід рахується від фактичного лічильника до нової цілі. Округлення здійснюється перед рухом: рівно 0,5 іде до меншого цілого тіка. Кнопка «СТОП», перерваний тест або запуск за обертами скидають відповідну серію. Рядок «Фактичний хід по колесу, см» показує відстань за енкодером.
